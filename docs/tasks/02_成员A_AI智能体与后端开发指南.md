# 成员 A：AI 智能体与后端开发指南

版本：V1.1（按参赛指南修订）｜执行期：2026-10-09～10-15｜全部时间为北京时间

统一依据：[01_项目总任务大纲.md](01_项目总任务大纲.md)。本文任务编号 A00～A09，接口和数据格式以总纲第4～7节为准。

## 1. 你的交付目标

你要让真实数据沿一套后端流动：保存想法、调用真实模型、创建实验草稿、发布、保存回答、算统计、生成复盘、导出报告，并留下可查询的工具记录。

你拥有全部 HTTP 路由、schema、数据库与服务层。B给你模板名和页面字段需求，不能自行改后端字段；C给你失败复现和测试，不另起后端。你不承担复杂UI和参赛材料统稿。

不要先研究多Agent框架、向量数据库或自主代码生成。P0只有三个工具，按固定顺序运行；真实调用和数据库效果比框架名称重要。

## 2. 开始前的准备

- [ ] 用Python 3.11创建虚拟环境，与B/C保持一致。
- [ ] 建仓库并加入总纲目录；保护 `main`，个人开发使用 `feat/a-*`。
- [ ] 创建 `.gitignore`，排除 `.env`、虚拟环境、data数据库、缓存和未脱敏证据。
- [ ] 确认一个已有模型账号可用、费用/额度可覆盖试用；不把密钥发到群聊或文档。
- [ ] 创建 `.env.example`，使用总纲的9个配置名。
- [ ] 在10/10上午冻结可运行依赖；保留精确版本，C复现后再合并。

开发依赖起步：fastapi、uvicorn、jinja2、pydantic、httpx、python-dotenv；测试加入pytest、playwright，由C验证所需浏览器安装。使用JSON提交，不为了普通表单再增加复杂上传组件。

先用最小脚本调用一次真实模型，输入一句不含个人数据的测试信息，记录成功/失败、模型名和时间。只记录密钥是否配置，不记录值。若仍不能调用，立即告诉B/C，允许他们用明确标识的test样例继续开发。

## 3. 按顺序完成的任务

### A00｜今晚锁定契约与可用模型（30～60分钟）

1. 和B确认总纲的创建JSON、题型、题号、API包装和页面路由。
2. 和C确认测试使用独立 `DATABASE_PATH`，真实试用用另一数据库/real项目。
3. 选择一个可用供应商，填写适配器的接口形式；不要假设不同供应商JSON模式完全相同。
4. 提交仓库骨架和 `.env.example`，将具体管理员账号另行安全配置。

交接：B拿到固定字段即可写页面；C拿到启动入口即可复现。验收：真实模型最小请求成功，或者有明确失败原因与负责人。

### A01｜基础服务、访问保护和建表（约2～3小时；10/10上午）

1. `config.py`读取配置，缺少关键值启动报可读错误，不输出密钥。
2. `db.py`创建总纲六表；启用外键；每个请求独立连接，用参数化SQL。
3. 用项目唯一运行锁约束同项目只有一条running记录；可用SQLite部分唯一索引覆盖 `project_id WHERE status='running'`。
4. `auth.py`采用HTTP Basic；保护全部管理页面/API，401包含登录挑战。管理写入检查受控同源Origin和固定 `X-Requested-With` 头；测试也传合法Origin。
5. `main.py`注册 `/health`、静态目录与模板。健康接口不调用模型，不暴露配置。
6. 启动时清理中断的run和tool的running日志，标记为failed/INTERRUPTED。P0只部署一个worker。
7. 将数据库路径目录自动建立；C不需要手动运行多条SQL。

验收：健康接口200；未登录管理401；授权后首页可打开；启动两次不会重复建表或丢数据。

### A02｜项目接口与统一schema（约2小时；10/10中午交接）

1. `schemas.py`写项目创建、landing、question、plan、answers、statistics、review模型，包含总纲的长度限制。
2. 项目创建、列表、详情接口完全按总纲第6节返回。创建返回 `project_id`，不是另一套 `id` 字段。
3. `repositories.py`集中保存与读取，路由不复制SQL。
4. 注册统一异常处理，422也用 `error.code/message/fields`；对数据库和上游错误返回脱敏说明。
5. 详情固定返回 `project,plan,experiment,latest_report_meta,running_run_id`，不存在项为null；项目摘要中提供派生status。
6. 向B/C提交可运行OpenAPI与一个test项目的请求/响应样例。

验收：创建→刷新→重启后同一项目仍存在；预算负数、空名称、超长idea均拒绝。C执行T01。

### A03｜模型适配与计划输出（约3～4小时；10/10下午）

1. `llm_client.py`只暴露一个统一函数：输入系统提示词和数据，输出模型文本及脱敏调用信息。
2. 使用供应商官方接口；SDK/HTTP只选一种实现。给HTTP请求设置40秒超时，不加自动重试。
3. `plan.txt`要求模型输出总纲第7.2节结构：3假设、4～6题、具体服务信息、执行步骤、下一步任务。
4. 用户提供的idea作为数据传入，不拼接成系统指令；禁止宣称未调查的市场结论为事实。
5. 若返回整段JSON代码围栏，可仅移除包裹整个响应的围栏；不从杂乱文字里猜JSON，不用 `eval`。
6. `json.loads`后做Pydantic和跨字段校验：题号、选项ID、假设引用、题型与options匹配。
7. 非法输出本次失败，返回 `LLM_OUTPUT_INVALID`；不静默换成示例计划。C用mock触发该分支。

验收：至少一个真实输入产生合法计划；换一条输入可产生相关内容；raw错误不泄露密钥。每次实际模型HTTP调用记录时间、模型名、是否成功；有供应商token用量才记录，无则写未提供。

### A04｜工作流、工具日志与草稿（约2～3小时；10/10晚）

实现三个工具名，拼写固定：

| 工具 | 输入 | 成功效果 / 输出 |
| --- | --- | --- |
| `make_validation_plan` | project_id；数据库读取项目字段 | 返回校验后的plan；日志中记字段摘要/假设数/题数 |
| `create_experiment` | project_id、校验后的plan | 计划和实验配置在同一事务保存；返回experiment_id |
| `analyze_experiment` | experiment_id | 读取回答快照、统计、调用模型、保存报告；返回report_id与回答数 |

前两个由 `POST /api/projects/{project_id}/plan` 顺序执行。第三个在A07接入review路由。

具体实现顺序：

1. 在短事务插入 `agent_runs(status=running)`，冲突返回409。
2. 分别为两个工具插入开始记录，提交后执行；不在HTTP模型等待时持有写锁。
3. 生成结果先放内存，create工具成功时原子保存plan、实验和关联结果引用。
4. 首次创建生成随机public_token；未发布重生成整体替换该实验草稿，保持experiment_id/token不变。
5. 任一步失败将tool与run标为failed；不覆盖之前成功草稿，不留下半份新计划。
6. `finally`路径确保运行释放；错误返回run_id便于C定位。
7. `GET /api/projects/{project_id}/runs`和 `GET /api/runs/{run_id}` 返回持久日志，B可在请求未完成时查询。

验收：T02/T03/T10。计划请求开始后，其他连接仍能读取日志和提交另一个项目的回答。时间线是实际日志，不是前端生成的动画。

### A05｜草稿编辑、发布与公开提交（约3～4小时；10/11上午）

1. 草稿GET、PATCH与预览路由采用同一实验数据，A传入B的service/survey模板；预览附 `is_preview=true`，公开页为false。
2. PATCH接受完整landing/questions，但只允许文本、选项label与required变化；ID、题型、选项结构不变，不能破坏假设引用。项目运行中拒绝编辑，避免草稿被并发覆盖。
3. 发布操作拒绝运行中项目；检查结构有效；写入一次 `published_at`，重复发布返回同一时间和链接。
4. 公开服务页与问卷仅接受已发布token；草稿或无效token一律404。
5. 发布后编辑与重生成计划均409 `EXPERIMENT_LOCKED`；服务器执行，不只靠UI。
6. 提交接口只按数据库中的已发布题目校验。将空的可选回答规范化为省略；多选排序并去除顺序差异，但重复值直接报错。
7. UUID幂等以数据库唯一约束兜底：同内容返回原ID，不同内容409；并发重放也不能新增两条。
8. 简答长度与必答条件在服务器检查，拒绝consent=false，不保存直接身份信息。

交给B：真实分享地址、提交返回、422字段说明。验收：T04/T05/T06/T12；C用手机提交后你查询到实际记录。

### A06｜程序统计与原始反馈读取（约2小时；10/11下午）

1. `statistics.py`输入已发布questions与回答列表，输出总纲统计对象；函数内部不调用模型、不依赖页面文字。
2. 为每题算answered_count；选择题输出全部选项，包括0次选项；多选用作答份数做分母。
3. 用2位小数展示percentage；零分母返回null。
4. 返回文字回答的 `response_id` 与text，空文本不计有效回答。
5. 返回整个实验的response_count和cutoff_response_id。不同实验回答ID可以不连续，不用最大ID充当数量。
6. 原始反馈与统计接口只允许管理员，不放在公开路径。

验收：C执行T07；你手动检查固定样本的66.67%分母，避免“看起来合理”就通过。

### A07｜复盘Agent、统计快照与导出（约3～4小时；10/12上午）

1. review路由只在已发布实验上运行；创建run与 `analyze_experiment` tool日志。
2. 在同一SQLite读取事务里读取题目和该实验所有回答，再计算统计快照；关闭连接后才请求模型。
3. `review.txt`传入原项目、3条假设、冻结题目、统计和文字回答；明确文字回答是外部数据，不是指令。
4. 要求固定review结构、引用存在、局限、最多3项行动；小样本不得宣称市场成功或付费需求已验证。
5. 校验h1～h3、assessment状态和evidence_refs，response_id须来自本快照，option_id须属于指定题；零回答由程序强制不足状态。
6. 保存 `statistics_json/review_json/response_count/cutoff_response_id`；旧报告保留，新失败不影响旧成功报告。
7. 详情/报告GET计算stale：当前回答数或最大ID与快照不同即true；新增回答时status回到collecting。
8. `reports.py`根据保存的快照生成Markdown，不临时拼接最新统计。包含数据来源、real/test、生成时间、run_id、题目计数与分母、结论/局限/行动。
9. 下载路由 `GET /api/projects/{project_id}/report.md` 使用附件文件名；无报告404。report页面使用B模板。

验收：T08/T09；同一项目先零反馈复盘，再提交真实回答再复盘，数量和结论有依据地变化；生成报告期间新增回答留给下一次快照。

## 5. 如何分阶段让 AI 编程

每次只让AI修改一个小范围，先读现有代码和总纲；一次任务完成并验证后再进行下一项。不要要求“一次写完完整创业平台”。

可直接复制的起始提示：

```text
请先读取 docs/tasks/01_项目总任务大纲.md 和成员A指南。
本轮只做 A01+A02：Python 3.11、FastAPI、sqlite3、统一JSON响应、
HTTP Basic管理保护、六表初始化、项目创建/列表/详情。
沿用总纲的路径、字段、错误码，不新增框架、不做前端、不生成假调研。
先说明将修改的文件，再实现；给出启动方法及创建后重启仍可读取的验证步骤。
不要读取或输出.env密钥，.env.example仅用占位值。
```

后续提示把范围改成A03+A04、A05、A06、A07，每轮要求“不改已冻结契约；如必须变更先列影响并等团队确认”。遇到报错提供最小请求、脱敏错误、当前schema，不把真实反馈整库或API Key发送给AI。

AI完成后你必须检查：有没有真的请求模型；有没有写数据库；有没有mock悄悄混入real路径；统计是否纯代码；失败是否释放锁；权限是否覆盖每个管理路由。

## 6. 遇到障碍时怎么处理

- 模型账号问题：先查base URL、模型名、授权、额度；只改适配器，不换整套工程。
- JSON不稳定：简化提示词和限制长度；本次报错并允许重试，不使用示例“补全成功”。
- SQLite锁定：缩短事务、每次连接独立、模型前关闭连接、保持单worker；不立即迁移PostgreSQL。
- 编辑界面复杂：与B保留文本编辑，不做拖拽题库；发布锁定仍由服务器保证。
- 复盘引用错误：按schema拒绝，不自动把不存在的引用改成真实证据。
- 10/12晚仍未跑通：取消全部P1，与B/C聚焦一条输入→表单→回答→报告链路。
