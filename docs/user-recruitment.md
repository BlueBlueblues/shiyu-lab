## 1. 目标与边界

| 项目 | 团队目标 | 说明 |
| --- | --- | --- |
| 邀请人数 | 5～6 人 | 团队目标，**不是赛事最低要求**；招不满就如实记录 |
| 其中有活动组织经验者 | 1～2 人 | 决定样本是否贴近“社团负责人”这一目标客户 |
| 试用时间 | 10/12～10/13 | 每人约 10～15 分钟 |
| 试用形态 | 参与者用**自己的设备**打开公开问卷 | 尽量独立操作；需要帮助时记人工干预 |

明确的口径：

- 这是**需求验证**，不承诺已交付任何活动报名系统，也没有任何付费要求；
- 不收集姓名、学号、手机号、微信号等直接身份信息；
- test 项目的回答**不进**真实样本；误混时应重建干净的真实实验并说明旧数据不可用；
- 公开链接可能收到无法核实的提交，此时分别汇报“实际参与人数”与“有效回答份数”。

## 4. 邀请时可以照抄的话术

> 我在做一个“帮社团做活动报名网页”的小项目，现在还在验证需求阶段，想请你花 10 分钟
> 用手机填一份 4 道题的问卷，说说你组织活动时报名这块的真实情况。
> 完全是需求调研，不用付费，也不会要你的姓名或手机号。问卷里只记匿名编号。

邀请时不要说的：

- “我们已经有 XX 个客户 / 已经成交”；
- “愿意了解就等于愿意付费”；
- “这个报名系统已经做好了，你可以用”。

## 5. 每次会话记录什么

写进 [`user-test-log.csv`](user-test-log.csv)，字段固定为：
`participant_code,has_organizing_experience,session_time,attempt_count,success_count,issue,feedback_note`。

| 字段 | 填法 |
| --- | --- |
| `participant_code` | 匿名编号 `P01`… |
| `has_organizing_experience` | `yes` / `no`；不确定写 `unknown` |
| `session_time` | 北京时间，精确到分钟，如 `2026-10-12 20:35` |
| `attempt_count` | 受控试用中记录的提交尝试次数（含失败重试） |
| `success_count` | 其中成功的次数；同一 UUID 重放不重复计成功 |
| `issue` | 页面/交互问题的一句话描述；没有写 `none` |
| `feedback_note` | 参与者的短评价或观察；**脱敏后**才能提交 Git |

**一人一行。** 重复点击不是多个独立用户：同一参与者重试只增加 `attempt_count`。

### 指标口径（与成员C指南 C05 一致）

| 指标 | 计算来源 | 汇报注意事项 |
| --- | --- | --- |
| 实际参与人数 | 匿名试用会话去重 | 不是数据库回答数量 |
| 有效回答份数 | 当前 `real` 实验数据库 | 不把 test 回答计入 |
| 提交成功率 | 受控试用 `success_count` 合计 / `attempt_count` 合计 | 只代表受控试用范围；无尝试记录写“未测” |
| Agent 耗时 | `agent_runs` / `tool_calls` 的开始与结束时间 | 计划与复盘分别报告 |
| 模型调用次数 | `llm_client` 实际 HTTP 调用日志 | 不能用工具次数代替 |
| 人工干预次数 | 人工记录 | 事先定义一次干预：重试、改文案、帮助操作等 |
| 用户评价与问题 | 实际反馈与观察 | 不补写不存在的满意度 |

## 7. 数据保护

- 公开页面不显示其他人的原始回答、运行日志、密钥或管理链接；
- 对外材料只用脱敏截图，隐去参与者意外填入的个人信息；
- 原始反馈限制访问；收到删除请求由团队处理；
- 不把真实反馈数据库提交到 Git。
