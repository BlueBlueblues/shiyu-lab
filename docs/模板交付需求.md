## C. 模板逐个需求

### C1. `base.html`（公共布局）

**必需内容**

1. `<!DOCTYPE html>`、`<html lang="zh-CN">`、`<meta charset="utf-8">`
2. `<meta name="viewport" content="width=device-width, initial-scale=1">` ← **手机端显示的前提**
3. 页面标题 block：`{% block title %}`
4. 样式引用：`<link rel="stylesheet" href="{{ url_for('static', path='/app.css') }}">`
5. 脚本引用（放 body 末尾）：`<script src="{{ url_for('static', path='/app.js') }}" defer></script>`
6. 内容 block：`{% block content %}`
7. **管理布局与公开布局分离**：
   - 管理页（`is_preview` 场景/工作台）允许显示管理导航
   - **公开页（`/e/{token}`、`/e/{token}/survey`）不得出现任何管理导航、项目列表、日志入口、管理员链接**

**建议实现方式**：`base.html` 只放最小公共骨架；用 `{% block header %}` 让公开页留空。不要用 `if is_admin` 这类模板里拿不到的变量猜状态。

**验收**：公开页 HTML 源码里搜索 `admin`、`登录`、`run-log`、`日志`，均无命中。

### C2. `experiment_edit.html`（草稿编辑）

**路由**：`GET /experiments/{experiment_id}/edit`（仅管理端；发布后只读）

**需要 A 传入的 context**

```jinja
experiment = {
  id, project_id,
  landing: {title, summary, target_users, value_proposition, features[], disclaimer},
  questions: [{id, type, title, required, options:[{id,label}]}],
  published_at            # 非空即"已发布"，页面只读
}
project = {id, name}
```

**可编辑范围（严格，不得扩大）**

| 可编辑 | 不可编辑 |
| --- | --- |
| `landing.title` | 题目 **ID** |
| `landing.summary` | 题 **型**（`single`/`multiple`/`text`） |
| `landing.target_users` | **新增/删除题** |
| `landing.value_proposition` | **新增/删除选项** |
| `landing.features`（多行文本，每行一项） | `hypotheses.question_ids` 关联 |
| `landing.disclaimer` | — |
| 每个 `question.title` | — |
| 每个 `option.label` | — |
| 每个 `question.required`（勾选框） | — |

**必需操作**

1. 逐题渲染，`single`/`multiple` 显示选项列表（label 可编辑），`text` 不显示选项
2. 保存按钮：`data-testid="experiment-save"` → `PATCH /api/experiments/{id}`，body 提交**完整** `{landing, questions}`
3. 保存成功后按钮**恢复可用**（E2E 靠这个判断完成）
4. 保存失败按 `error.code` 显示可读提示；`409 EXPERIMENT_LOCKED` 提示「已发布，若要改题请创建下一轮项目」
5. 预览链接：服务页预览 + 问卷预览
6. 发布后（`published_at` 非空）：所有输入框 `readonly`/`disabled`，保存按钮隐藏或禁用，页面顶部提示已发布

**字段命名（C 的 E2E 依赖，固定）**

| 元素 | 选择器 |
| --- | --- |
| title 输入 | `input[name="title"]` |
| summary 输入 | `textarea[name="summary"]` |
| target_users 输入 | `input[name="target_users"]` |
| value_proposition 输入 | `input[name="value_proposition"]` |
| features 输入 | `textarea[name="features"]` |
| disclaimer 输入 | `textarea[name="disclaimer"]` |
| 题目标题输入 | `input[name="question-{question_id}-title"]` |
| 选项 label 输入 | `input[name="option-{question_id}-{option_id}-label"]` |
| required 勾选 | `input[name="question-{question_id}-required"]` |

**验收**：改一处文字 → 保存 → 刷新页面 → 修改仍在；未发布时 `<input>` 可编辑；已发布时只读。

### C4. `survey.html`（问卷页）

**路由**：预览 `GET /experiments/{experiment_id}/preview/survey`、公开 `GET /e/{public_token}/survey`

**需要 A 传入的 context**

```jinja
questions = [{id, type, title, required, options:[{id,label}]}]
is_preview = bool
public_token            # 或 survey_url，见 §G 问题 2
```

**三类题的渲染规则（严格）**

| `type` | 控件 | 提交值 | 前端必答校验 |
| --- | --- | --- | --- |
| `single` | 同题同 `name` 的 `radio` | 选项 ID 字符串 `"o1"` | 必须选 1 项 |
| `multiple` | `checkbox` 组 | 选项 ID 字符串数组 `["o1","o2"]` | 至少选 1 项 |
| `text` | `textarea` | 字符串 | 去空格后非空 |

**必需行为**

1. 每题用 `<fieldset>` + `<legend>` 分组；`<label for>` 绑定控件；**选项 label 不是选项 ID**
2. 必答题显示标记；简答 `maxlength="1000"`
3. 可选题未作答 → **从 `answers` 对象省略**（不发空串/空数组）
4. 知情说明区域：用途、参与自愿、联系团队删除数据的方式；不计姓名/手机/学号
5. 同意勾选：`data-testid="survey-consent"`；**未勾选不得提交**
6. 提交按钮：`data-testid="survey-submit"`
7. 成功提示：`data-testid="submission-success"`（**必须可见**）
8. 请求中禁用按钮；失败保留已填答案并显示可读信息，可重试
9. `is_preview=true`：整表禁用提交，显示「草稿预览，不能提交」

**验收**：未登录手机浏览器能填完三类题并提交成功，数据库多一条记录；403/422/500 都有可读提示。

## E. 脚本 `app.js`

### E1. 统一请求封装

1. 一个函数处理 JSON 请求，读取 `data` 或 `error{code,message,fields}`
2. 管理写请求：自动带 `X-Requested-With: FirstOrderLab` 且同源（`credentials: 'same-origin'`）
3. 统一处理错误码：`401`（提示重新登录）、`403`、`404`、`409`（`RUN_IN_PROGRESS` / `EXPERIMENT_LOCKED` / `IDEMPOTENCY_CONFLICT`）、`422`（按 `fields` 定位到具体输入框）、`502`/`504`（模型侧问题，提示可手动重试）
4. 超时预算：管理请求 70 秒；超时后**不自动重试**，提示「可手动重试」

### E2. 提交状态

- 请求中显示「处理中」并 `disabled` 按钮；结束后恢复
- 失败不被当作成功（**关键**：只有 HTTP 2xx 且无 `error` 才算成功）

### E3. 问卷 UUID 幂等（总纲 §7.3）

1. 进入问卷页（本次填写开始）生成一个 UUID，存 `localStorage`（key 含 token，避免跨问卷串号）
2. 请求体：

```json
{"client_submission_id":"<uuid>","consent":true,"answers":{"q1":"o1","q4":["o1","o2"]}}
```

3. 网络失败重发 → **沿用同一 UUID + 同一 payload**
4. 用户修改答案后重新提交 → **生成新 UUID**（否则后端按"同 UUID 不同内容"返回 409）
5. 首次 **201**、幂等重放 **200** 均显示成功；`duplicate=true` 时**不得**显示"又新增了一条"
6. 成功后显示提交时间/收条并禁用再次点击
7. `localStorage` 只存 UUID 与成功标记，**不存业务数据**

**验收**：断网重发不产生第二条记录；改答案再提交不会误报 409。
