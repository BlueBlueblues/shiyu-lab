# API 选型：需求统计问卷与核价清单

版本：V1｜建立：C｜日期：2026-10-10
用途：选出一个模型供应商（大纲 §3.1 要求**只选一家**），并估算团队总成本。

---

## 0. 先分清三类用量（混在一起问，谁也答不上来）

大纲 §3.1 规定产品的模型调用集中在 A 的 `llm_client.py`，
但「谁用 AI」和「谁写代码调 AI」是两件事。

| 类别 | 是什么 | 谁在用 | 怎么计费 | 要不要写进参赛材料 |
| --- | --- | --- | --- | --- |
| **① 产品运行时调用** | 网页上点「生成验证方案」「生成复盘」时，代码自动调模型 | 只有 A 的代码调；但消耗它的人包括 A 调试、C 做真实模型冒烟、C 组织的真实试用、录屏演示 | 按 token 付费 | **要**。这是 OPC「实际投入/成本」的证据（A09） |
| **② 开发用 AI 编程助手** | 三个人写代码时用的 Cursor / Copilot / 通义灵码 / 网页聊天等 | A、B、C 各一份 | 通常是包月订阅 | **要**。大纲要求披露「AI 编程工具与使用范围」 |
| **③ 做参赛材料** | 写作品介绍、视频脚本、申报书 | 主要 C | 网页版额度或包月 | 要，并入②一起披露 |

**两条重要结论：**

1. **②③ 用哪家，和 ① 用哪家，不必相同。** 大纲只限制「产品不要同时接多个供应商」，
   没有限制成员自己用什么编程助手。
2. **成本大头大概率是 ②，不是 ①。** 大纲给的工时预算是
   A 18～23 小时、B 14～18 小时、C 技术 8～12 小时 + 试用材料 8～12 小时，
   合计约 56 小时的人机协作；而产品运行时一次调用只有几千 token。

> 大纲 §1.2 特别写明：**「预算 100 元是输入示例，不是已发生的成本」**，
> 所以最终报告要填**实际发生额**，未测就写「未测」，不能拿 100 元当成支出。

## 1. 问卷（可直接转发给 A、B、C）

### 1.1 三人通用（7 题）

1. 你打算让 AI 帮你做哪些**最花时间**的活？请列 3 项，并说明每项大概占你多少时间。
2. 从今天到 10/15，你每天大概能投入几小时？（大纲工时预算：A 18–23h、B 14–18h、C 技术 8–12h + 材料 8–12h）
3. 你打算**用什么工具**写代码？（VS Code + 插件 / Cursor / 命令行 Agent / 网页聊天 / 还没定）
4. 你现在手上**已经有的 AI 账号**是什么？哪一家、什么套餐、还剩多少额度、什么时候到期？
5. 你希望**怎么付费**：按量用多少付多少，还是包月？你个人能接受的**金额上限**是多少？
6. 你的电脑**能不能稳定访问国外网站**？（决定能否用 OpenAI / Claude / Google 系）
7. 你有没有**开发票/报销**的需要？（学校项目经费可能要发票，有些供应商开票门槛高）

### 1.2 给 A（后端 + 产品调模型）

8. 产品运行时，你预计要跑多少次「生成计划」和「生成复盘」？
   **提示：** 点一次生成方案 = 1 次；改一次提示词重跑 = 又 1 次；开发期反复调试很容易累积到几十上百次。
9. 你调试时会不会**保留模型的原始输出**？保存多久？（有些供应商要求不得长期留存输出）
10. 你预计提示词有多长？（几百字 / 几千字；这直接决定每次的输入 token）
11. **这个供应商能不能稳定返回严格 JSON？**（见第 3 节第 1 条，这是硬指标）
12. 超时按大纲设 40 秒，你实际能接受的最慢响应是多少秒？
13. 复盘时要读全部问卷回答，你预计一次要读**多少条回答**？会不会超上下文？
14. 你需要**缓存折扣**吗？（同一段提示词反复调用能否便宜）
15. **演示当天模型挂了怎么办？** 大纲 §11 允许展示「带时间和 run_id 的已完成真实记录」，
    你打算怎么留这些记录？

### 1.3 给 B（前端）

16. 你主要让 AI 干什么？（写 HTML/CSS/JS / 调样式 / 解释报错 / 生成整页）
17. 你预计每天问多少次？每次是「贴一小段」还是「把整个文件丢给它改」？
    （后者单次消耗可能是前者的 10 倍以上）
18. 你需要 AI 一次看**多个文件**吗？
19. 你需要 AI **画图/生成图标**吗？（有些 API 不带多模态，要另买单）
20. 你会不会用 AI 生成整个页面再粘贴？大概几个页面？

### 1.4 给 C（测试与材料）

21. 写测试时，你让 AI 一次生成**一个文件**还是**整套用例**？
22. 你要跑几次**真实模型冒烟**？（大纲 §10 要求至少 1 次计划 + 1 次复盘）
23. 真实试用阶段，你预计触发几次**复盘**？（每来一批新回答就要重新复盘一次）
24. 做材料（作品介绍 PDF、视频脚本、申报书）你会用 AI 吗？大概多少字？
25. 你能拿到**每次调用的详细用量记录**吗？（C05 指标表要求报告「实际模型 HTTP 调用次数」，
    不能拿工具调用次数冒充）

## 2. 产品必须支持的能力（这些不是「用量」，是「必须有」）

按大纲逐条推导，选型时逐项打勾，缺一项就不能选：

| # | 要求 | 来自 |
| --- | --- | --- |
| 1 | 能被 `httpx` 直接 HTTP 调用（不接受只能用专属 SDK 的） | §3.1 |
| 2 | 能设置 **40 秒超时** | §5 |
| 3 | 支持 **JSON 输出模式**，且能稳定返回严格 JSON | §7.2 校验很严，不合规就报 `LLM_OUTPUT_INVALID` |
| 4 | 能查询 **token 用量**（用于 OPC 成本证据） | A09 |
| 5 | 网络可从国内稳定访问 | 实测 pypi.org 直连不通，必须实测供应商接口 |
| 6 | 单价低（学生自付，100 元是量级参考） | §1.2 |
| 7 | 上下文足够长（复盘要读全部回答） | §7.5 |
| 8 | 并发/限流够用（三人共用一个 Key 开发时不能互相卡死） | §5 |

**不需要、因此不必为它多付钱的能力：**

- **函数调用 / 自主工具调用**：大纲 §3.3 明确 P0 用**确定性工作流**，由程序按固定顺序调三个工具，
  不需要模型自己决定调什么。所以「工具调用能力」不是选型理由。
- **流式输出**：§5 用同步请求 + 按钮禁用，不需要流式。
- **多模态/画图**：产品不产出图片。
- **超长上下文**：一次复盘只读一个小样本（试用目标 5～6 人）。

## 4. 怎么把答案算成一个数

### 4.1 产品运行时成本（类别①）

```
单次计划成本 = 输入token数 × 输入单价 + 输出token数 × 输出单价
单次复盘成本 = 输入token数 × 输入单价 + 输出token数 × 输出单价
总成本① = 计划次数 × 单次计划成本 + 复盘次数 × 单次复盘成本
```

**token 数从哪来？** 别猜。让 A 用最小的真实调用跑一次，
把结构按大纲 §7.2 / §7.5 生成出来，然后**从供应商控制台抄真实用量**。

按大纲的输出结构，量级大致是：

| 调用 | 输入（含提示词） | 输出 |
| --- | --- | --- |
| 生成计划（3 假设 + 3～6 题 + 服务页文案） | 约 1～2k token | 约 2～3k token |
| 生成复盘（结论 + 3 条假设评估 + 反馈 + 局限 + 行动） | 约 3～6k token（要带全部回答） | 约 1.5～3k token |

> 这两个数只是**估算锚点**，用来判断量级；真实数字必须实测后回填。

### 4.2 算例（价格用占位数字，**必须换成官网实数**）

假设：输入 2 元/百万 token，输出 8 元/百万 token；
开发调试 150 次计划 + 30 次复盘。

```
单次计划 = 1.5k×2/1e6 + 2.5k×8/1e6 = 0.003 + 0.020 = 0.023 元
单次复盘 = 4k×2/1e6   + 2k×8/1e6   = 0.008 + 0.016 = 0.024 元
总成本① = 150×0.023 + 30×0.024 ≈ 3.45 + 0.72 ≈ 4.2 元
```

**结论：产品 API 的钱通常是个位数到几十元，不是主要成本。**
真正要盯的是类别②的编程助手订阅（三份）。

## 5. 决策顺序建议

1. **先过第 2 节的硬指标**（不满足的直接淘汰）；
2. **再看第 3 节的单价与限流**（限流比单价更容易坑人：演示时被限流就是事故）；
3. **再看有没有 token 套餐**（如果 ① 的量真的上来了，套餐可能更划算）；
4. **最后算总额**，并把它拆成「产品运行」和「开发工具」两行写进材料；
5. 选定后**只接一家**（§3.1），把供应商、模型名、版本记进
   `docs/technology-sources.md`，把 Key 放进 `.env`，**不发群聊、不写文档**。
